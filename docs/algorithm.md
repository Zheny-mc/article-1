# Алгоритм ACFSA: два математических механизма

## Назначение

ACFSA (Adaptive Context Filtering and Structuring Algorithm) располагается между первичным Retriever и LLM. Он не меняет исходный документ и не заменяет векторный поиск. Его задача — преобразовать расширенный список кандидатов `D0` в компактный набор фрагментов `C*`, сохранив релевантные сведения и происхождение каждого фрагмента.

```text
Q -> Retriever(top-N) -> D0
                         |
                         v
             1. Адаптивная релевантность
                         |
                         v
                    D1 (filtered)
                         |
                         v
             2. Подавление избыточности
                         |
                         v
              C* (compact context)
                         |
                         v
                   LLM / Agent
```

## Обозначения

- `Q` — пользовательский запрос;
- `D0 = {d1, ..., dn}` — кандидаты первичного поиска;
- `E(x)` — embedding текста `x`;
- `s_i` — семантическая релевантность фрагмента `d_i` запросу;
- `D1` — кандидаты после адаптивной фильтрации;
- `A` — множество уже отобранных MMR-фрагментов;
- `K` — максимальное число фрагментов итогового контекста.

---

## Механизм 1. Адаптивная оценка релевантности

### 1. Векторное представление

Модель эмбеддингов отображает запрос и фрагменты векторы одного пространства:

`q = E(Q)`, `v_i = E(d_i)`.

Для L2-нормализованных векторов косинусная близость равна скалярному произведению:

`s_i = cos(q, v_i) = (q · v_i) / (||q||2 ||v_i||2)`.

В реализации используется `intfloat/multilingual-e5-small`. E5 ожидает префикс `query: ` для запроса и `passage: ` для документа. В эксперименте модель и ревизия должны быть одинаковыми для всех сравниваемых методов.

### 2. Устойчивый адаптивный порог

Фиксированный порог (например, `0.7`) часто переносится плохо между моделями и типами вопросов. Поэтому порог вычисляется отдельно для каждого запроса по распределению оценок кандидатов `S = {s_1, ..., s_n}`.

Медиана:

`m = median(S)`.

Медианное абсолютное отклонение:

`MAD = median_i(|s_i - m|)`.

Устойчивая оценка разброса:

`sigma_r = 1.4826 * MAD`.

Адаптивный порог:

`T(Q) = max(T_min, m - beta * sigma_r)`.

Где:
- `T_min` — абсолютная нижняя граница семантической близости, настраиваемая на validation;
- `beta >= 0` — коэффициент допуска. Больший `beta` смягчает фильтр, меньший делает его строже.

Фрагмент проходит фильтр, если:

`d_i in D1 <=> s_i >= T(Q)`.

Медиана и MAD устойчивее к единичным экстремальным кандидатам, чем среднее и стандартное отклонение. Вычитание `beta * sigma_r` задаёт нижнюю границу относительно центра распределения: при небольшом разбросе порог не завышается над всеми близкими друг к другу релевантными оценками. `T_min` не позволяет пропускать слабую выдачу только потому, что все кандидаты имеют низкие score.

**Граничное поведение:** если ни один кандидат не проходит `T_min`, формируется пустой контекст (сигнал об отсутствии подтверждающих материалов), а не принудительно выбирается слабейший результат. Если MAD равен нулю, порог становится `max(T_min, median)`.

### Пример

Пусть `S = {0.92, 0.90, 0.88, 0.45, 0.32}`. Тогда `m=0.88`, `MAD=0.04`, `sigma_r=1.4826*0.04=0.0593`. При `beta=1.0` и `T_min=0.60`:

`T(Q) = max(0.60, 0.88 - 0.0593) = 0.8207`.

Остаются три фрагмента с оценками `0.92`, `0.90`, `0.88`; два низкорелевантных кандидата отбрасываются.

**Ограничение:** embedding similarity — приближение релевантности, но не проверка истинности, актуальности или нормативной применимости документа. Версия, дата действия, раздел, пункт и статус документа должны сохраняться как метаданные.

## Механизм 2. Выявление и подавление семантической избыточности

### 1. Межфрагментная близость

После первого механизма в `D1` могут остаться фрагменты, которые отвечают на вопрос, но повторяют друг друга. Для двух фрагментов вычисляется:

`r_ij = cos(E(d_i), E(d_j))`.

Точное дублирование текста удаляется отдельно дешёвым сравнением нормализованных строк. MMR предназначен для семантических повторов, а не только буквальных копий.

### 2. Критерий MMR

Для каждого ещё не выбранного кандидата вычисляется:

`MMR(d_i) = lambda * RelNorm(d_i,Q) - (1-lambda) * max_{d_j in A} cos(E(d_i), E(d_j))`.

Где:
- `RelNorm` — cosine similarity, ограниченная диапазоном [0, 1] без min-max-нормализации по текущим кандидатам;
- `A` — уже выбранный набор;
- `lambda in [0,1]` — баланс релевантности и разнообразия;
- для первого выбранного блока штраф за избыточность равен нулю.

Первый член максимизирует соответствие запросу. Второй штрафует кандидата за сходство с уже включёнными блоками. Таким образом, MMR выбирает не просто самые похожие на запрос документы, а те, которые добавляют новую информацию к текущему контексту.

### Пример

При `lambda=0.7`:

- D2: `Rel=0.90`, `maxSim=0.95`; `MMR=0.7*0.90 - 0.3*0.95 = 0.345`.
- D3: `Rel=0.87`, `maxSim=0.30`; `MMR=0.7*0.87 - 0.3*0.30 = 0.519`.

D3 выбирается раньше D2, потому что он чуть менее релевантен по отдельности, но приносит больше новой информации.

### Жадный отбор

1. Инициализировать `A = empty`.
2. Для каждого кандидата из `D1 \ A` вычислить MMR относительно `A`.
3. Добавить в `A` кандидата с максимальным MMR.
4. Повторять до `|A|=K` или пока кандидаты не закончатся.
5. Вернуть выбранные фрагменты с исходными метаданными.

В коде отрицательная косинусная близость для штрафа обрезается до нуля: отрицательная близость не должна превращаться в искусственное вознаграждение разнообразия.

## Полная процедура

1. Первичный Retriever возвращает `top-N` кандидатов.
2. Для каждого кандидата вычисляется `s_i = cos(E(Q), E(d_i))`.
3. По текущему распределению score вычисляются `median`, `MAD`, `sigma_r`, `T(Q)`.
4. Кандидаты ниже `T(Q)` и `T_min` отбрасываются.
5. Точные дубликаты удаляются с сохранением лучшего экземпляра и источника.
6. Выполняется MMR-отбор не более `K` фрагментов.
7. Контекст формируется из текста и метаданных: `source`, `doc_id`, `chunk_id`, релевантность, версия и страница/раздел при наличии.
8. Контекст передаётся LLM; логируются scores, порог, выбранные и отброшенные блоки, токены и latency.

## Вычислительная сложность

Пусть `N` — число кандидатов после первичного поиска, `p` — размерность embedding, `K` — лимит итоговых фрагментов. Вычисление query-document similarity требует порядка `O(Np)`. Расчёт MAD — `O(N log N)`. Жадный MMR в простой реализации — порядка `O(KNp)` (при вычислении сходства кандидата с уже выбранными блоками); предварительное построение полной матрицы сходства требует `O(N^2 p)` времени и `O(N^2)` памяти. Для типичного небольшого `top-N` достаточно жадного варианта без полной матрицы.

## Параметры, подлежащие калибровке

- `N`: число первичных кандидатов;
- `T_min`: минимальный уровень семантической близости;
- `beta`: строгость адаптивного порога;
- `lambda`: компромисс релевантности и разнообразия;
- `K`: лимит фрагментов или контекстный token budget.

Настройка производится только на validation; тестовая выборка остаётся нетронутой до итоговой оценки.
