# Алгоритм ACFSA: два математических механизма

## 1. Назначение и место в RAG-конвейере

**ACFSA (Adaptive Context Filtering and Structuring Algorithm)** — этап предварительной обработки результатов поиска, расположенный между первичным Retriever и LLM-агентом. Он не заменяет индекс и не переписывает исходные документы. Его задача — преобразовать расширенный ранжированный список кандидатов в компактный контекст, сохранив значимые факты и происхождение каждого фрагмента.

```text
Запрос Q
   |
   v
Единый Retriever (top-N) --> D0
   |
   v
Механизм 1: адаптивная релевантность
   |
   v
D1: кандидаты выше query-specific порога
   |
   v
Точная дедупликация
   |
   v
Механизм 2: MMR-подавление семантической избыточности
   |
   v
C*: компактный контекст с источниками и метаданными
   |
   v
LLM / AI-агент
```

Ядро метода состоит **из двух математических механизмов**:

1. адаптивная оценка релевантности и отсечение нижнего хвоста нерелевантных кандидатов;
2. выбор взаимно дополняющих фрагментов с подавлением семантической избыточности методом MMR.

Упаковка итогового контекста с заголовками и метаданными — необходимая операция структурирования результата, но не третий математический механизм.

## 2. Обозначения

- `Q` — пользовательский запрос;
- `D0 = {d1, ..., dN}` — первые `N` кандидатов общего Retriever;
- `E(x)` — embedding текста `x`;
- `s_i` — близость кандидата `d_i` к запросу;
- `S = {s_1, ..., s_N}` — распределение оценок для одного запроса;
- `D1` — кандидаты после адаптивного порога;
- `A` — множество уже выбранных MMR-фрагментов;
- `K` — максимальное число фрагментов итогового контекста;
- `T_min`, `beta`, `lambda` — параметры, подбираемые только на validation.

---

## 3. Механизм 1. Адаптивная оценка релевантности

### 3.1. Векторизация запроса и документов

Embedding-модель отображает запрос и каждый фрагмент в одно векторное пространство:

```text
q   = E(Q)
v_i = E(d_i)
```

Для L2-нормализованных векторов косинусная близость равна скалярному произведению:

\[
s_i = \operatorname{cos}(q,v_i) = \frac{q^T v_i}{\|q\|_2\|v_i\|_2}.
\]

В проекте используется `intfloat/multilingual-e5-small`. Для модели E5 применяются разные префиксы: `query: ` для запроса и `passage: ` для фрагмента. Модель, ревизия и способ нормализации фиксируются для всех сравниваемых методов.

Оценка `s_i` означает семантическую близость, а не вероятность истинности, актуальности или юридической применимости текста. Для нормативных документов дата, версия, статус действия, номер пункта и источник должны храниться отдельно в метаданных.

### 3.2. Робастное распределение оценок

Для каждого запроса отдельно рассчитывается набор `S`. Центральный уровень задаётся медианой:

\[
m = \operatorname{median}(S).
\]

Разброс оценивается медианным абсолютным отклонением:

\[
MAD = \operatorname{median}_i(|s_i-m|).
\]

Устойчивая оценка масштаба:

\[
\sigma_r = 1.4826 \cdot MAD.
\]

Медиана и MAD менее чувствительны к единичным экстремальным score, чем среднее и стандартное отклонение. Коэффициент `1.4826` приводит MAD к масштабу оценки стандартного отклонения при нормальном распределении.

### 3.3. Адаптивный порог

Порог задаётся формулой:

\[
T(Q)=\max(T_{min},\;m-\beta\sigma_r).
\]

Кандидат сохраняется, если:

\[
d_i\in D_1 \iff s_i\geq T(Q).
\]

Интерпретация параметров:

- `T_min` — абсолютная нижняя граница близости. Она не позволяет пропустить слабые фрагменты лишь потому, что весь набор кандидатов плохой.
- `beta >= 0` — коэффициент допуска. Чем он больше, тем ниже порог и мягче фильтрация; чем меньше, тем строже отсечение.
- `m` — медианная близость кандидатов для текущего запроса.
- `sigma_r` — робастная мера разброса текущих оценок.

**Почему используется `median - beta * sigma_r`, а не `mean + alpha * std`.** Для нижнего отсечения формула «среднее плюс стандартное отклонение» может поднять порог выше части релевантных результатов, особенно когда большинство кандидатов и так имеет высокие оценки. Вычитание робастного разброса задаёт нижнюю границу относительно центра распределения и менее зависит от единичных выбросов. При этом формула остаётся эвристикой: она не выдаёт откалиброванную вероятность релевантности, а ее параметры необходимо проверять на validation.

### 3.4. Пример расчёта

Пусть:

```text
S = {0.92, 0.90, 0.88, 0.45, 0.32}
T_min = 0.60
beta = 1.0
```

Тогда:

```text
m         = 0.88
MAD       = 0.04
sigma_r   = 1.4826 * 0.04 = 0.0593
T(Q)      = max(0.60, 0.88 - 1.0 * 0.0593) = 0.8207
```

Фрагменты со score `0.92`, `0.90`, `0.88` проходят фильтр; `0.45` и `0.32` отбрасываются.

### 3.5. Граничные условия

- Если ни один фрагмент не достигает `T_min`, алгоритм возвращает пустой контекст (сигнал об отсутствии подтверждающих материалов), а не принудительно выбирает слабейший результат.
- Если `MAD = 0`, порог становится `max(T_min, median)`.
- Если `S` пуст, на выходе нет кандидатов.
- `T_min` и `beta` подбираются на validation и фиксируются до теста.
- Порог рассчитывается по кандидатам текущего запроса; его нельзя интерпретировать как глобальный порог для любой embedding-модели и любого корпуса.

## 4. Механизм 2. Подавление семантической избыточности

### 4.1. Точные и семантические дубликаты

После адаптивной фильтрации фрагменты могут частично или полностью повторять друг друга. Сначала применяется дешёвая точная дедупликация: текст приводится к `casefold`, пробельные последовательности схлопываются, затем для одинаковых нормализованных строк оставляется экземпляр с наибольшей релевантностью.

Точная дедупликация не обнаруживает перефразирования. Для семантического повтора используется косинусная близость между embedding-векторами документов:

\[
r_{ij}=\operatorname{cos}(E(d_i),E(d_j)).
\]

### 4.2. Критерий Maximal Marginal Relevance

Для каждого ещё не выбранного кандидата вычисляется:

\[
MMR(d_i)=\lambda\,RelNorm(d_i,Q) -(1-\lambda)\max_{d_j\in A}\operatorname{cos}(E(d_i),E(d_j)).
\]

Здесь:

- `RelNorm(d_i,Q)` — cosine similarity кандидата к запросу, ограниченная диапазоном `[0,1]` без min-max-нормализации относительно текущего набора;
- `A` — уже выбранные фрагменты;
- `maxSim` — максимальная близость кандидата к любому уже выбранному фрагменту;
- `lambda in [0,1]` — баланс релевантности и разнообразия.

Для первого выбранного блока множество `A` пустое, поэтому штраф за повторение равен нулю: первым выбирается самый релевантный кандидат. При последующих итерациях MMR уменьшает оценку кандидатов, которые слишком похожи на уже включённые блоки. Отрицательная cosine similarity в штрафе обрезается до нуля — она не должна становиться искусственным вознаграждением за разнообразие.

Параметр `lambda` интерпретируется так:

- `lambda = 1`: чистый выбор по релевантности, штраф за повторение выключен;
- `lambda = 0`: после первого фрагмента приоритет отдаётся разнообразию;
- промежуточные значения задают компромисс. `0.7` используется только как стартовое значение, не как доказанный оптимум.

### 4.3. Пример

Пусть `lambda = 0.7`.

Для `D2`, где `Rel=0.90` и `maxSim=0.95`:

\[
MMR(D2)=0.7\cdot0.90-0.3\cdot0.95=0.345.
\]

Для `D3`, где `Rel=0.87` и `maxSim=0.30`:

\[
MMR(D3)=0.7\cdot0.87-0.3\cdot0.30=0.519.
\]

Хотя D2 немного ближе к запросу, D3 предпочтительнее: он в меньшей степени повторяет уже выбранную информацию.

### 4.4. Жадный MMR-отбор

1. Инициализировать `A = empty`.
2. Если `A` пусто, выбрать оставшийся кандидат с максимальной `RelNorm`.
3. Для каждого оставшегося кандидата вычислить MMR относительно `A`.
4. Добавить в `A` кандидата с максимальным MMR. При равенстве сохранять исходный порядок Retriever, чтобы результат был детерминированным.
5. Повторять до `|A| = K` либо пока кандидаты не закончатся.
6. Вернуть выбранные фрагменты в порядке MMR-отбора.

MMR не является удалением «всего похожего». Он выбирает компромисс между релевантностью и дополнением уже выбранного контекста. Для нормативной документации тематически похожие фрагменты могут устанавливать разные условия, исключения или редакции; поэтому метаданные и экспертная проверка остаются обязательными.

## 5. Формирование структурированного контекста

После двух математических механизмов выбранные фрагменты упаковываются с сохранением:

- текста;
- `source`, `doc_id`, `chunk_id`;
- relevance score и, при необходимости, MMR score;
- страницы, раздела, номера пункта, редакции и даты действия — если эти сведения доступны.

Например:

```text
[Фрагмент 1 | источник: safety_instruction.md | doc_id: safety_instruction
 | chunk_id: safety_instruction::0001 | relevance: 0.9100]
Текст подтверждающего фрагмента...

---

[Фрагмент 2 | источник: quality_manual.md | doc_id: quality_manual
 | chunk_id: quality_manual::0002 | relevance: 0.8600]
Текст дополнительного фрагмента...
```

Такой формат сохраняет трассируемость: ответ агента можно связать с конкретным источником. Структурирование не должно объединять противоречащие положения или терять версию нормативного документа.

## 6. Полный псевдокод

```text
ALGORITHM ACFSA(Q, Retriever, E, N, K, T_min, beta, lambda)

1. D0 <- Retriever(Q, top_n=N)
2. if D0 is empty: return empty_context
3. q <- normalize(E("query: " + Q))
4. for each d_i in D0:
       v_i <- normalize(E("passage: " + d_i.text))
       s_i <- cosine(q, v_i)
5. m <- median(s_1, ..., s_N)
6. MAD <- median(abs(s_i - m))
7. sigma_r <- 1.4826 * MAD
8. T <- max(T_min, m - beta * sigma_r)
9. D1 <- {d_i in D0 : s_i >= T}
10. D1 <- remove_exact_duplicates(D1, keep_highest_relevance=True)
11. A <- empty list
12. while D1 is not empty and len(A) < K:
       if A is empty:
           choose d* with maximum relevance
       else:
           choose d* maximizing:
             lambda * RelNorm(d*, Q)
             - (1-lambda) * max_similarity(d*, A)
       append d* to A
       remove d* from D1
13. C* <- format(A, preserving_source_and_metadata=True)
14. return C*
```

## 7. Вычислительная сложность

Пусть `N` — число первичных кандидатов, `p` — размерность embedding, `K` — размер итогового контекста. Расчёт query-document similarity требует `O(Np)`. Расчёт медианы и MAD — `O(N log N)`. Жадный MMR без предварительного построения полной матрицы similarity — порядка `O(KNp)` при повторном сравнении кандидатов с выбранными векторами. Предварительное построение полной матрицы требует `O(N²p)` времени и `O(N²)` памяти. Для небольшого top-N достаточно жадного варианта.

---

## 8. Параметры и ограничения

Настройке на validation подлежат `N`, `K`, `T_min`, `beta`, `lambda` и при необходимости token budget. Порог и веса зависят от embedding-модели, языка, типа корпуса и характера запросов.

Cosine similarity не проверяет истинность и актуальность сведений. MMR может убрать тематически близкие, но содержательно разные положения. Поэтому алгоритм должен сохранять происхождение фрагментов, а для критически важных нормативных документов требуется проверка версии, даты действия и раздела. Эффективность ACFSA подтверждается не формулой или прохождением unit-тестов, а воспроизводимым сравнительным экспериментом на размеченной тестовой выборке.
