# ACFSA — эксперимент адаптивной фильтрации контекста в RAG

Репозиторий содержит исследовательский прототип алгоритма **Adaptive Context Filtering and Structuring Algorithm (ACFSA)** для предварительной фильтрации и структурирования контекстных фрагментов перед передачей RAG-ориентированному AI-агенту.

## Идея алгоритма

ACFSA состоит из двух математических механизмов:

1. **Адаптивная оценка релевантности.** Для каждого кандидата `d_i` вычисляется cosine similarity `s_i = cos(E(Q), E(d_i))`. Затем по оценкам текущего запроса рассчитывается устойчивый порог `T(Q) = max(T_min, median(S) - beta * 1.4826 * MAD(S))`. Фрагменты ниже порога отбрасываются.
2. **Подавление семантической избыточности.** После удаления точных дубликатов применяется Maximal Marginal Relevance (MMR): `MMR(d_i) = lambda * RelNorm(d_i,Q) - (1-lambda) * maxSim(d_i,A)`. Это помогает выбирать не только близкие к запросу, но и дополняющие друг друга фрагменты.

Подробное математическое описание и примеры вычислений: [`docs/algorithm.md`](docs/algorithm.md). Блок-схема: [`docs/flowchart.mmd`](docs/flowchart.mmd). План и протокол эксперимента: [`docs/experiment_plan.md`](docs/experiment_plan.md).

## Быстрый запуск

Рекомендуется Python 3.11 или новее.

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
pytest -q
python scripts/run_experiment.py --config configs/default.yaml
```

При первом запуске `sentence-transformers` скачает модель `intfloat/multilingual-e5-small`. Для первичной проверки код использует демонстрационные синтетические Markdown-документы. Это проверка воспроизводимости программного контура, а не научное подтверждение эффективности на ГОСТах или документах предприятия.

Результаты сохраняются в `outputs/latest/`:

- `results_per_query.csv` — метрики для каждого запроса и метода;
- `summary.csv` — агрегированные показатели;
- `audit.json` — scores, адаптивные пороги и выбранные MMR-фрагменты;
- `run_metadata.json` — параметры и сведения о запуске;
- `tokens_comparison.png`, `recall_comparison.png`, `ndcg_comparison.png`, `latency_comparison.png` — сравнительные графики.

## Подключение собственного корпуса

1. Поместите собственные `.pdf`, `.txt` или `.md` документы в отдельную локальную папку, например `data/private_corpus/`.
2. Измените `corpus.directory` в конфигурации на эту папку.
3. Подготовьте собственный `qa.jsonl`: одна JSON-запись на строку, обязательные поля — `question` и `relevant_doc_ids`; желательно также указать `reference_answer`.
4. Проверьте `doc_id`: по умолчанию он равен имени файла без расширения.
5. Не загружайте конфиденциальные документы, извлечённые тексты и персональные данные в публичный Git-репозиторий.

Пример строки `qa.jsonl`:

```json
{"question":"Как регистрируется несоответствие?","relevant_doc_ids":["quality_manual"],"reference_answer":"Запись получает уникальный номер и содержит описание отклонения и корректирующее действие."}
```

## Настройка параметров

В `configs/default.yaml`:

- `retrieval.top_n` — сколько кандидатов возвращает общий первичный Retriever;
- `retrieval.top_k` — максимальное число фрагментов в контексте каждого метода;
- `acfsa.beta` — коэффициент адаптивного допуска;
- `acfsa.min_threshold` — нижняя граница similarity;
- `acfsa.lambda_param` — баланс релевантности и разнообразия в MMR.

`beta`, `min_threshold`, `lambda_param`, `top_n` и `top_k` нужно калибровать на validation-выборке. Не подбирайте их по тестовым запросам.

## Генерация ответов через LLM (необязательно)

По умолчанию `llm.enabled: false`, поэтому проект сравнивает качество retrieval и объём переданного контекста без расходования API-токенов. Чтобы получить пары ответов Baseline/ACFSA для экспертной слепой оценки, установите переменные окружения или заполните локальный `.env` (сам файл `.env` игнорируется Git):

```text
OPENAI_API_KEY=ваш_ключ
OPENAI_BASE_URL=https://ваш-openai-compatible-endpoint/v1
LLM_MODEL=название-модели
```

Затем включите `llm.enabled: true` в YAML. Поддерживается OpenAI-compatible Chat Completions endpoint; точный base URL и имя модели задаются провайдером. В `answers_for_blind_review.csv` сохранятся ответы и пустые поля для экспертной оценки. Не публикуйте ключи и не включайте закрытый контекст в репозиторий.

## Сравниваемые методы

- **Baseline RAG:** общий Retriever → top-K → контекст.
- **Adaptive only:** тот же Retriever → адаптивный порог → top-K.
- **MMR only:** тот же Retriever → удаление точных дубликатов → MMR.
- **ACFSA-RAG:** тот же Retriever → адаптивный порог → удаление точных дубликатов → MMR.

Скрипт поддерживает все четыре режима; список задаётся параметром `experiment.methods` в YAML. По умолчанию запускаются все четыре режима.

## Метрики

Скрипт рассчитывает Precision@K, Recall@K, MRR, nDCG@K, число токенов, число выбранных фрагментов, число уникальных источников, среднюю попарную близость выбранных фрагментов и время обработки. При включённой LLM-генерации ответы оцениваются экспертами отдельно по корректности, полноте, обоснованности источниками и наличию неподтверждённых утверждений.

Результаты необходимо интерпретировать на тестовой выборке. Нельзя заранее приписывать методу процент снижения токенов или роста точности: эти величины должны быть измерены.

## Ограничения

- Косинусная близость не доказывает истинность и актуальность фрагмента.
- Параметры порога зависят от модели эмбеддингов и корпуса.
- MMR может удалить тематически похожие, но содержательно разные нормы; это контролируется параметром `lambda_param` и экспертным анализом ошибок.
- Демонстрационный корпус синтетический и предназначен только для проверки работы проекта.
